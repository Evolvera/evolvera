- **Fix root causes, never work around:** reproduce, read the actual error and state, and ask why until you reach the first wrong decision in the code. Never ship a guard, retry, sleep, swallowed error, clamped value, or flag that hides a bug. Fix the pattern everywhere it occurs; if the root cause is out of scope, land the in-scope fix and report the rest open.
- **Minimal surface:** the smallest root-cause fix, not the smallest diff. Reach every caller, test, and config it breaks.
- **SoC / SRP:** one coherent responsibility per module; separate behavior, data, config, presentation, tests, and docs. Reuse existing helpers; abstract only after three real repetitions.
- **Match the repository:** follow its structure, import boundaries, naming, and style; put new code where its feature lives. Derive migration names from the tool and existing files, never invent or reuse a timestamp.
- **No comments in code:** make intent clear through names and types. Allowed only: license headers, tool directives, public API doc comments, and links for external constraints. A correctness-rule suppression (`@ts-ignore`, `eslint-disable` of a real-bug rule) is a defect. Leave untouched code alone.
- **Trust boundaries:** validate inputs, use explicit errors, preserve authorization and tenant checks, parameterized queries, exact money, and idempotency.
- **Leave no trash:** create scratch files, clones, logs, containers, and processes in one run-owned place (`.tmp/` or the system temp dir), remove them before reporting, and say what you kept and why. Give what you build a lifetime (pruned caches, rotated logs).
- **Use the CPU:** run heavy work in parallel within ~80% of logical CPUs, with isolated resources per worker; never loosen tests under contention.
- **Prove a launcher before scaling it:** run the exact command once with a short timeout and observe real progress; close stdin for children that need no input; set a no-progress deadline and stop on the first stalled instance.
