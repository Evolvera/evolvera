# Patch Notes — 2026-09-25 (branch `NatiamG`)

Para quem for levar a `NatiamG` para a `main`: o que mudou, por quê, o que muda no comportamento, como foi verificado e o que ainda precisa de atenção.

## Resumo

A `NatiamG` está **29 merges e 52 commits à frente da `main`**, e a `main` é ancestral dela, então o merge não tem conflito. O trabalho foi feito pelo protocolo Copy Thief (skill incluída nesta branch). Cada mudança nasceu de uma issue do GitHub Project "NatiamG", teve teste antes da correção, passou por avaliação independente (validator e, nos casos de risco, qa) e entrou na `NatiamG` por um merge commit com o número do PR e da issue.

Resultado principal: **`node scripts/run-tests.mjs` passou de 11 aprovados / 40 falhos para 57 aprovados / 0 falhos / 1 excluído** no Windows, e o pi-studio deixou de aceitar comandos de qualquer página aberta no navegador.

Cada linha abaixo aponta para a issue, onde estão a discussão, as reprovações e a retrospectiva. Os commits trazem, no corpo, "Problema / Por quê / O que muda e como verificar".

## Mudanças de comportamento (leia antes de atualizar a `main`)

| O que muda | Quem é afetado | Issue |
|---|---|---|
| A API `/api/*` do pi-studio exige o header `X-PI-Studio-Token`. O token é gerado a cada vez que o servidor sobe, vem só na página servida e é conferido junto com `Host` e `Origin`. **`/api/health` também exige o token.** Chamadas por `curl` ou scripts sem o token recebem 401/403. | Quem usa o pi-studio por fora do navegador | #7 |
| A página do pi-studio (que carrega o token) só é servida para Host `127.0.0.1`/`localhost`/`[::1]` ou para o `PI_WEB_HOST` configurado. | Acesso por outro nome de host | #7 |

## Destaques por área

### Segurança do pi-studio (`interface/`)
- **#7**: autorização única antes de qualquer rota `/api`, checando Host, Origin (inclusive `null`) e token. A comparação é feita com `timingSafeEqual`. O stream de eventos (SSE) usa cookie `HttpOnly; SameSite=Strict`, então o token nunca vai na URL.
- **#8**: `serveStatic` deixou de conferir o caminho por prefixo de string, que deixava passar uma pasta vizinha como `public-evil/` (CWE-22). Agora usa `path.relative` sobre a URL crua. Percent-encoding malformado responde 400, não 500. Foram testadas 9 variantes de traversal por HTTP cru, todas com 403 e sem vazamento (evidência na issue).

### Interface
- **#26**: o smoke da interface usa pasta de agente e projeto temporários e entrou no runner.
- **#10**: um responder único para o diálogo. Chamadas simultâneas aguardam o mesmo envio, e uma falha de rede permite tentar de novo.
- **#9**: aviso de encerramento do PI, a partir do evento `process_exit` do servidor, e reinício pela rota do projeto.

### Instalador
- **#11**: `scripts/test/install-sh.smoke.mjs` roda o `install.sh` real com HOME, USERPROFILE e XDG temporários e com `pi`/`npm` falsos. Antes de chamar o instalador, confere que `npm`, `npm.cmd` e `pi` resolvem para os falsos, e compara os destinos reais antes e depois.
- **#12**: falhas de `pi install` ficaram visíveis (ver tabela acima).

### Testes e runner
- **#6**: `node scripts/run-tests.mjs` é o runner único. Ele classifica cada suíte como sem estado, tmpdir próprio ou excluída; suíte sem classificação aparece no resumo mas não roda.
- **#23**: os smokes procuravam o SDK do PI num caminho fixo de outra máquina. `extensions/test/lib/pi-sdk.mjs` resolve `PI_SDK_ROOT` → `npm root -g` → caminhos relativos.
- **#32, #37**: no Windows, symlink de diretório virou junction; symlink de arquivo e `chmod 0600` sem privilégio viram `SKIP` visível, só no win32.
- **#49**: limite de tempo próprio por suíte, com justificativa. A `ct.test.mjs` tem 120 s; as demais seguem com 30 s.

### Plastic-memory (não é instalada por padrão)
- **#33**: 3 smokes estavam desatualizados e foram corrigidos, citando o commit que mudou o comportamento, sem afrouxar asserção.
- **#41**: defeito real. `project/search.ts` recusava caminhos absolutos do Windows (`C:\...`), e agora usa `path.isAbsolute`.
- **#14**: a suspeita de que o backfill parava depois de 8 janelas foi **refutada** pelo código. Entrou só um teste de regressão.

### Ferramentas e documentação
- Skill **Copy Thief** em `skills/copy-thief/`: método, templates e `ct.mjs` para operar o GitHub Project (#18).
- **#15**: `docs/AGENTS.md` alinhado aos fluxos do `SYSTEM.md`.
- **#17**: `docs/copy-thief/mapa-do-projeto.md`.
- **#16**: README com os comandos slash, como rodar os testes e como desinstalar.
- **#27**: `.codegraph/` no `.gitignore`.

## Limitações conhecidas / não verificado

- As mudanças do pi-studio (#9, #10) **não foram testadas num navegador real**, só pelo smoke com PI falso.
- #10: não foi verificado um segundo pedido de UI chegando com o primeiro diálogo aberto.
- #8: um symlink dentro de `interface/public/` que aponte para fora seria servido. Hoje não há nenhum versionado.
- A suíte foi validada só no Windows. Os `SKIP` de symlink e permissão rodam integralmente em Linux/macOS, mas não foram executados nesses sistemas nesta campanha.

## Como levar para a `main`

1. Nesta máquina ou em outra, salve o que houver de local em `.pi/recovery/` e `.pi/build/` (ver #13).
2. Abra um PR `NatiamG` → `main`. A `main` é ancestral da `NatiamG`, então não há conflito.
3. Depois do merge: `./install.sh` (ou `install.ps1`). Se usar o codegraph, mescle a entrada em `~/.pi/agent/mcp.json`. Rode `node scripts/run-tests.mjs`.
