O que mudou

Menos ambiguidade, mais entrega verificável

Antes, muitas decisões de modelo, escopo e recuperação dependiam de instruções longas ou do estado do chat. Esta atualização torna essas regras explícitas em agentes, skills, configurações e gates de validação.

Roteamento explícito

Cada agente declara modelo, esforço de raciocínio e identidade visível no runtime.

Escopo controlado

Scouts são read-only por capacidade; validators começam no alvo solicitado e evitam ruído do repositório.

Planos executáveis

Tasks compactas carregam objetivo, mudança, acceptance, validação e checkpoint — sem duplicar boilerplate.

Estado remoto confiável

O Flow reconstrói o trabalho a partir de GitHub, PRs e branches antes de retomar uma issue.

Como escolher o agente

Como o PI decide o processo

Três níveis de orquestração

O sistema escolhe o nível de coordenação pela consequência, dependências e risco — não apenas pela quantidade de arquivos.

Direct OrchestratorPara edição trivial e conhecida: localizar, alterar, validar e concluir sem criar uma cadeia artificial.
Focused SubagentsPara investigação ou execução delimitada: scout para evidência, builder adequado ao risco, validator apenas quando o custo de falha justificar.
Planned DeliveryPara mudanças longas, compartilhadas ou de alto risco: plano, tarefas atômicas, dependências, checkpoints e gates selecionados.

Contrato compacto de task

Tasks de planner deixam de repetir TODO/TILL-DO e princípios genéricos. A unidade de execução responde cinco perguntas: Goal, Change, Acceptance, Validation e Checkpoint. O execution envelope carrega o estado runtime, recovery e limites de patch.

Planejamento com gate

/plan-heavy ficou mais rigoroso

  • Aceita contratos compactos e legados, sem perder compatibilidade de planos anteriores.
  • Normaliza paths e bloqueia traversal, glob, target absoluto e referências operacionais inseguras.
  • Exige concordância entre SCHEDULE.md, arquivo da task, agente declarado e arquivos tocados.
  • Impede executar em paralelo tasks que se sobrepõem em um arquivo compartilhado.
  • Modela validators review-only como PASS | BLOCKED, sem commits vazios.
Regra prática: um checkpoint comprova uma mudança escrita; um validator independente comprova que a mudança pode desbloquear o próximo nó do DAG.

O harness possui smoke test em Node e workflow GitHub Actions. O teste cobre recovery, gates de validator, consistência de targets, serialização de overlap, paths inseguros e conteúdo de envelopes.

Entrega contínua

Flow usa GitHub como autoridade

Cache local e memória de chat não são mais tratados como prova de ownership. Em cada continue ou chat novo, a reentrada busca Project, issues, PRs e branches remotas antes de decidir o que retomar.

Reconstruir o boardDescobrir Project v2, paginar issues e PRs, buscar todas as branches remotas e classificar inconsistências.
Claim verificávelUma issue é reclamada por assignee único + branch determinística flow/#N-slug + SHA confirmado.
Publicar e relerDepois de branch, PR ou mudança de status, o Flow relê a fonte remota e só então atualiza .pi/flow.
Concluir com mergedone exige PR correspondente com mergedAt != null; issue fechada ou PR fechado sem merge vira anomalia/blocker.
Não existe “transação mágica” entre Git e GitHub. O processo usa pós-condições lidas do remoto, nunca força push, não apaga branch remota silenciosamente e não confunde cache com lock.

Checklist para uma instalação nova

  1. Faça git pull.
  2. Execute ./install.sh no Unix ou .\install.ps1 no Windows.
  3. Reinicie ou recarregue o PI para carregar agentes, modelos e tema.
  4. Use /settings se quiser confirmar o tema ativo.

O que ainda exige atenção

Limitações conhecidas

  • O instalador PowerShell foi revisado, mas não executado neste ambiente porque pwsh não estava disponível.
  • O protocolo Flow remoto-first foi validado estruturalmente, mas não foi exercido contra um Project GitHub real nesta rodada para não mutar um board externo.
  • O tema do PI aceita tokens de cor. Efeitos de glow, blur e animação dependem do renderer do terminal/UI e não são parte do schema de tema.
