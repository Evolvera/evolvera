# `/usage`

`/usage` reports assistant-message token usage for the **current session branch**, grouped by provider and model. It reads the active branch on each invocation, so branch navigation and model changes are reflected without a persisted counter.

In the managed application runtime, `/usage` also requests subscription quota for the selected PI account when invoked. It supports stored Claude (`anthropic`) and OpenAI Codex (`openai`) OAuth credentials only. It shows the selected PI account id, provider window duration, percent used and remaining, reset time in UTC, and fetch time. Window lengths come from the provider response for Codex; Claude's response fields represent its five-hour and seven-day windows. Missing, expired, unsupported, invalid, timed-out, or rejected credentials/requests are shown as unavailable, never as zero. Quotas are independent of local assistant transcript entries.

These are undocumented/private provider HTTP routes, not public API guarantees. Requests are read-only GETs, use a five-second timeout, do not follow redirects or retry, and never refresh credentials. Successful data is cached only in memory for up to five minutes within that selected runtime instance; errors are not cached. No provider response, token, email, or workspace identifier is logged or displayed. Managed quota collection reads only the explicitly selected account's credential store on `/usage`; metadata startup is inert and no global account scan or profile/entitlement lookup occurs. The default/unmanaged extension remains local-only and truthfully reports **“Cotas dos provedores: não consultadas”**.

The TUI uses compact rounded Unicode cards, with **Claude on the left and Codex on the right** when at least 100 inner columns are available; narrower terminals stack the cards. The board is capped at 140 cells and centered on very wide terminals. Each available quota window has a width-adaptive `▰▱` bar **filled by percent used**, plus explicit used/remaining percentages; the fill is discrete while the numbers retain the reported value. Usage of 75% or more is highlighted as a warning and 90% or more as an error. Unavailable windows have no fabricated bar or zero. `↺` marks scheduled reset timestamps; reset/fetch dates explicitly use UTC. The local branch and activity sections remain separate. RPC/plain-text preserves its existing metrics and adds the requested banked-reset field without terminal decoration.

Codex's `↻ Banked resets` is the earned, redeemable reset count, **not** the number of upcoming scheduled resets or a money/credit balance. It reads only optional `rate_limit_reset_credits.available_count` from the existing usage GET. A nonnegative safe integer (including explicit zero) is accepted; absent/null/invalid data is shown as **não informado**, never guessed from quota percentages, dates, or detail-list length. The count uses the same in-memory cache and account binding as the quota report. No extra request, account scan, app-server process, redemption, or POST is introduced. Claude has no equivalent documented field in the reviewed sources, so no Claude count is fabricated.

The field and identical usage route are evidenced by [OpenAI Codex's pinned backend-client tests](https://github.com/openai/codex/blob/21c16161191ff965031d1ac41fe9046011610743/codex-rs/backend-client/src/client/rate_limit_resets_tests.rs) and [official app-server rate-limit documentation](https://developers.openai.com/codex/app-server#6-rate-limits-chatgpt). This source contract is not proof that a particular account currently returns the optional count.

The local section shows input, output, cache-read, cache-write, and total tokens, plus SDK-reported estimated cost components and total. Cache token categories are summed once alongside input/output, matching the SDK usage totals convention. Costs are values recorded in session usage data, not a provider account balance, invoice, or guarantee of final charges.

The activity calendar is titled **“Atividade desta branch — não é histórico global”** and counts assistant responses by their session-entry timestamps; it does not count real HTTP requests. It is anchored to the current UTC week, displays the last 53 weeks when the terminal width permits (or a labeled shorter recent window when narrow), and shows the UTC date range, month markers, dated-response total, and how many fall inside that window. Older dated responses remain in the branch total but are not placed in the displayed window. Missing, malformed, and future timestamps are excluded and reported as undated; if no valid response timestamps exist, the panel says no dated assistant responses are available. Calendar weeks use UTC boundaries.

The command is read-only and reads only the current branch; the managed quota requests above are the sole provider contact. Quota reports are not verified against real account data here. Neither quota nor local usage is persisted. RPC and print modes retain the plain-text notification/message output; if the TUI custom component API is unavailable, TUI falls back to a plain notification. Native `/session` remains unchanged.
