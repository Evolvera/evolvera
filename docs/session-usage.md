# `/usage`

`/usage` reports assistant-message token usage for the **current session branch**, grouped by provider and model. It reads the active branch on each invocation, so branch navigation and model changes are reflected without a persisted counter.

In TUI mode, `/usage` opens a closable, resizable Usage panel grouped by provider and model. It shows input, output, cache-read, cache-write, and total tokens, plus SDK-reported estimated cost components and total. Cache token categories are summed once alongside input/output, matching the SDK usage totals convention. The panel explicitly says **“Cotas dos provedores: não consultadas”**: no provider quotas, percentages, resets, credits, or expiry are displayed. Costs are values recorded in session usage data, not a provider account balance, invoice, or guarantee of final charges.

The activity calendar is titled **“Atividade desta branch — não é histórico global”** and counts assistant responses by their session-entry timestamps; it does not count real HTTP requests. It is anchored to the current UTC week, displays the last 53 weeks when the terminal width permits (or a labeled shorter recent window when narrow), and shows the UTC date range, month markers, dated-response total, and how many fall inside that window. Older dated responses remain in the branch total but are not placed in the displayed window. Missing, malformed, and future timestamps are excluded and reported as undated; if no valid response timestamps exist, the panel says no dated assistant responses are available. Calendar weeks use UTC boundaries.

The command is read-only. It does not contact providers, inspect authentication, read other session branches, or persist usage state. RPC and print modes retain the plain-text notification/message output; if the TUI custom component API is unavailable, TUI falls back to a plain notification. Native `/session` remains unchanged.
