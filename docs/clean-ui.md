# clean-ui

`extensions/clean-ui.ts` presents compact state/tool/path cards with semantic title and target colors, concise diff deltas, and bounded edit previews. Edit previews use thin Unicode framing at regular widths and drop the frame when narrow. Successful edits show this preview even while collapsed; other tool output remains expanded-only, and errors remain visible while collapsed. The two-line footer keeps model/thinking/cost/branch metadata separate from the context bar and extension statuses. It is enabled by default; use `/clean-ui status`, `/clean-ui off`, or `/clean-ui on` to inspect or toggle it. The preference is stored as `clean-ui.json` in Pi's agent directory. Disabling restores the stock footer, working indicator, hidden-thinking label, and stock tool rendering for new cards; existing cards redraw after `/reload`.

The working indicator uses an eight-cell Unicode comet (`◆`, `━`, `·`) with accent/success/muted colors and a 125 ms frame interval. Motion is scheduled by the SDK's existing working indicator, not another extension timer. It appears only while that native indicator is visible; it does not animate idle screens or claim that `/usage` fetches display a loading animation. The elapsed-time message and its turn-scoped reset remain unchanged, and `/clean-ui off` restores the stock indicator.

The footer reads live context percentage and registered mode/status values. Missing or invalid context usage is shown as unknown, and mode state comes only from the owning extension status/command. Todo reads and successful intermediate calls are hidden; successful creation/completion and errors remain visible. Tool execution, transcript results, model context, sidebar content, images, and general tool errors are not changed.

The isolated smoke test uses a copied extension and a run-owned fake SDK package. It checks bounded synthetic rendered output, ANSI stripping, Unicode cell widths, responsive widths, and preserved renderer behavior; it does not certify native terminal rendering. Publication requires a separate native TTY observation and a backup of the previous public extension source. Restore that backed-up source for rollback; do not reset credentials, settings, sessions, or replace the SDK. Repository tests never publish to the installed agent directory. Existing processes keep their loaded code; use a fresh PI 1.2 invocation to observe a published change.
