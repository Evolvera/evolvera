# clean-ui

`extensions/clean-ui.ts` adopts the existing thin-Unicode tool renderer and adds a compact context/mode footer. It is enabled by default; use `/clean-ui status`, `/clean-ui off`, or `/clean-ui on` to inspect or toggle it. The preference is stored as `clean-ui.json` in Pi's agent directory. Disabling restores the stock footer, working indicator, hidden-thinking label, and stock tool rendering for new cards; existing cards redraw after `/reload`.

The footer reads live context percentage and registered mode/status values. Missing or invalid context usage is shown as unknown, and mode state comes only from the owning extension status/command. Todo reads and successful intermediate calls are hidden; successful creation/completion and errors remain visible. Tool execution, transcript results, model context, sidebar content, images, and general tool errors are not changed.

The isolated smoke test uses a copied extension and a run-owned fake SDK package. It does not certify native terminal rendering. Publication requires a separate native TTY observation and a backup of the previous public extension source. Restore that backed-up source for rollback; do not reset credentials, settings, sessions, or replace the SDK. Repository tests never publish to the installed agent directory. Existing processes keep their loaded code; use a fresh PI 1.2 invocation to observe a published change.
